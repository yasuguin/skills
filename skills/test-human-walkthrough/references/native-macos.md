# macOS のネイティブアプリを触る

claude-in-chrome が使えない対象（SwiftUI / AppKit のアプリ、メニューバー常駐アプリ）を、
人間と同じ画面とキーボードで触るための手段。手順 1〜5 の流れと報告の形は SKILL.md のまま。
2026-10-17、音声入力のメニューバー常駐アプリで実施した結果が元になっている。

## ブラウザとの違い

ブラウザは裏のタブで完結するが、ネイティブアプリはユーザーの画面・前面アプリ・キーボードを
そのまま借りる。前面が入れ替わると、送ったキーやアプリが入力する文字がユーザーの作業中のアプリ
（ターミナルの Claude Code の入力欄など）に入る。これを防ぐ確認が、ブラウザには無い手順として加わる。

## 渡す前の確認（メインが行う）

1. 対象が起動しているか。`pgrep -fl <アプリ名>`。
   dev 版と配布版が並ぶアプリでは、パス（`.build/...` か `/Applications/...` か）まで見る。
2. 操作手段が通るか。`osascript -e 'tell application "System Events" to get name of every process whose name contains "<アプリ名>"'`
   が名前を返せば、ターミナル（Ghostty など）のアクセシビリティ権限がある。`screencapture -x <ファイル>` が
   空でない画像を作れば画面収録の権限がある。
3. 対象が画面上にあるか。`swift scripts/window-id.swift "<アプリ名>"` が ID を返すか、
   メニューバー項目の位置（`position of menu bar item 1 of menu bar 2` の Y が 0 以上か）で見る。
   全画面のターミナルが前面だと、メニューバーごと隠れて Y が負になり、ウィンドウは onscreen=false になる。
   画面上に無ければ、agent に渡さず、ユーザーに対象を出す場所の用意を頼む（下の「前面の奪い合い」）。
4. アプリが前面のアプリへ文字を入力する種類か（音声入力、テキスト展開、ペースト支援など）。
   設定ファイルの入力方式（キー入力で送るか、貼り付けで送るか）を読み、該当するなら
   入力先にする空の書類（TextEdit の新規書類など）を prompt で指定する。

## 操作

- System Events（`click`、`keystroke`、`key code`、メニューバー項目の `click`）と、座標クリック・
  修飾キーの長押しを CGEvent で投げる小さな swift スクリプト（`$TMPDIR` に置く）で操作する。
- 修飾キーだけのショートカット（左 Cmd + 左 Option の長押しなど）は、`flagsChanged` の CGEvent に
  左右を区別する device フラグ（`NX_DEVICELCMDKEYMASK` 0x8、`NX_DEVICELALTKEYMASK` 0x20 など）も
  含めて投げる。アプリが NSEvent の global monitor で左右を見ている場合、device フラグが無いと反応しない。
- 声が要る機能は、`say -v Kyoko "<発話>"` をスピーカーから流してマイクで拾わせる。音が出ることと、
  外部の音声認識 API を呼ぶかは、手順 1 でユーザーに聞いておく。最短録音時間の設定
  （そのアプリでは 2 秒）より十分長い文にする。
- **前面に文字が入る操作の直前に毎回**、frontmost のアプリ（System Events の `frontmost`）と
  AX の focused element が入力先の書類であることを確かめる。外れていたら実行しない。
  入力は離した数秒後に起きることがあるので、完了まで frontmost を数回見て、入力先から外れたら
  以降の入力系の操作をすべて止める。
- OS の許可ダイアログ（マイク・音声認識・画面収録など）を押すのは副作用として報告に書く。
  取り消し方（システム設定 → プライバシーとセキュリティ → 該当項目）も添える。

## 撮影

- 証拠はウィンドウ単位（`screencapture -x -o -l<WID>`）で撮る。WID は `scripts/window-id.swift` で、
  アプリ名を指定して引く（`swift window-id.swift "TextEdit"`）。
- メニューバーのメニュー・オーバーレイ・OS のダイアログはウィンドウ ID で撮りにくい。`-R x,y,w,h` で
  その範囲だけを撮る。全画面で撮ると、他のアプリやユーザーの別セッションの内容、デスクトップの
  ファイル名が写るので、全画面の 1 枚は観測にだけ使って消す。
- 動画は gotchas.md の「画面録画」と同じ手順で、`-l` か `-R` を付けて撮る。

## 前面の奪い合い

- 全画面のターミナルが前面だと、対象のメニューバー項目もウィンドウも画面外になる。2026-10-17 は
  全画面の Ghostty（tmux の中で Claude Code のセッションが動いていた）の裏に対象のアプリが隠れ、
  メニューバー項目は Y=-24、ウィンドウは onscreen=false だった。`open -a <アプリ>` でも前面に出なかった。
- 専用の Space に置いて Control+← で切り替えると、一時的には操作できた。ただし約 1.5 分後、
  OS のダイアログを閉じた直後に Ghostty が前面に戻った。何が前面を取ったかは特定できていない
  （候補: 同じ画面の他のエージェントセッションの出力・通知、bell による前面化）。
- このため、操作の途中でも前面が入れ替わる前提で動く。入れ替わったら入力系の操作を止め、
  ユーザーに次のどちらかを頼んでから再開する: 他の Claude Code セッションが動いていない時間に
  全画面のターミナルを解除して行う、または声やキーの操作だけユーザー本人にしてもらい、
  agent は画面と保存データの観測に回る。
- 終わったら、移った Space を元に戻す（Control+→ など）。
