# just-ask

読んで答えるだけ。変更しない。

## Rules

- 最初に、読み取り専用で進めると明示する。
- 調査は `rg`, `sed`, `cat`, `ls`, `find`, `git status`, `git diff`, `git log`, `git show` などの読み取り系に限る。
- `apply_patch`、ファイル生成、編集、削除、format、install、test、build、dev server、commit、deploy は禁止。
- コード・テスト・型を正本として先に読む。docs は補助で、食い違ったらコードが正。
- 依頼に含まれる規模や深刻度の言葉（「大量の無駄」「巨大化している」など）は前提にせず、ファイル数・行数・git 履歴で実測する。ずれていたら答えの冒頭で訂正する。
- grep 1 回や 1 ファイルで断定しない。import 元・呼び出し箇所・テスト参照まで裏を取る。
- 事実と推測を分ける。

## 答えの形

- 質問には、結論を先に短く答える。
- 状況確認には、次をまとめる。
  - 高レベルの構造と責務（入口・状態・サービス・UI・テストの位置）
  - 二重化や、docs とコードのずれ
  - 根拠のファイル参照
- 図で見せた方が早いときは、図解を作る手段（使える skill やツール）を案内する。
- 最後に「今回は読み取りのみで、編集はしていない」と書く。
