# コストの診断

Claude Code の利用を API の定価に換算し、料金を押し上げている内訳から、それを誘発しているルールを探す。
定額プラン（Pro / Max / Team）の枠で使った分も、従量課金（Enterprise の利用分・API 直契約）なら幾らかで比べる。
計算は `scripts/api_cost.py` が全部持つ（依存は Python 標準ライブラリだけ）。パスは skill のディレクトリが基準。

## 手順

1. 期間を決める。ユーザーの指定が無ければ、今月の 1 日から今日までにする。
   Claude Code は既定で 30 日を過ぎたログを消すので（`cleanupPeriodDays`）、それより前は残っていないことがある。
2. 実行する。

   ```sh
   uv run --no-project python -I scripts/api_cost.py --since 2026-10-01 --until 2026-10-28
   ```

   - 今日を含む直近 N 日なら `--since`・`--until` の代わりに `--days 7`。
   - `uv` が無ければ `python3 -I <同じパス> ...` で動く（3.11 以上）。
   - 期間は日本時間の暦日で切る。別のタイムゾーンなら `--tz America/Los_Angeles` のように渡す。
   - ログの場所が違えば `--projects-dir`。`CLAUDE_CONFIG_DIR` が設定されていればその下の `projects/` を見る。
   - 資料に数字を貼るとき、内訳を細かく見るときは `--json` で取る。
3. 内訳を読み、下の「内訳の読み方」で疑うルールを決める。高い軸のセッションを 1〜2 件、生ログ
   （`~/.claude/projects/**/*.jsonl`）で確かめてから原因と言う。
4. 報告は SKILL.md の共通の形に、先頭の内訳として合計・稼働日 1 日あたり・モデル別・種別・押し上げている軸の上位を
   出し、次の前提を添える。
   - 単価は API の定価で、全社契約の割引・税は含まない。
   - この端末のログだけ。ほかの PC や claude.ai・デスクトップアプリでの利用は入らない。
   - web 検索などのサーバーツールの従量料金は入らない。
5. 直したら、同じ長さの期間で回し直し、稼働日 1 日あたりで比べる。

## 内訳の読み方

料金はおおむね「1 応答あたりのコンテキスト × 応答の数 × モデルの単価」で決まる。どの因子が膨らんだかで疑う場所が変わる。

- **キャッシュ読みが大半**（1 応答あたりのキャッシュ読みが大きい）: 常時 prompt とコンテキストの肥大。
  instruction file・skill の一覧・MCP のツール定義・`@` import を疑う。削る手順はルールの最適化（`rule-placement.md`）。
  長いセッションを `/compact` せずに続けている場合もある。
- **1 時間キャッシュの書き込みが大きい**: セッションの開始や、待ちのあとの書き直しが多い。サブエージェントを
  細かく何度も起こしていないか、常時 prompt が頻繁に変わっていないか（日付や状態を差し込む hook）を見る。
- **サブエージェントの型が上位**: 型の定義（model・effort）と、委譲の指示を書くルールを疑う。安いモデルで足りる
  探索・実装を上位モデルの型に回していないか。速度の診断（`speed.md`）の委譲の指標と並べて読む。
- **特定の project・セッションが突出**: その repo の `AGENTS.md`（全リクエストに載る）、その repo で動く hook、
  ループした作業（同じテストの再実行、Stop hook の block の往復）を疑う。
- **モデル別で上位モデルが大半**: 既定モデルと、上位モデルへ切り替えるルール（advisor・fast mode を含む）を見る。

## 終了コード 2 で止まったとき

`error: 単価表に無いモデル` が出たら、新しいモデルが出て単価表が古い。推測した単価で計算し直さない。
公式の料金ページ（https://platform.claude.com/docs/en/about-claude/pricing）の Model pricing 表から、
そのモデルの 5 つの値を `PRICES` に足し、`PRICES` の上にある取得日も更新してから実行し直す。
単価が改定されたときも同じ手順で表を直す。

## 数え方（変えるときはテストも直す）

`tests/test_api_cost.py` が正本。要点だけ書く。

- 同じ応答は `message.id` と `requestId` の組で 1 回だけ数える。Claude Code は 1 つの応答を複数行に書き、resume すると別ファイルにも写すため、重複を除かないと倍以上になる。
- キャッシュ書き込みは 5 分と 1 時間で単価が違うので、`usage.cache_creation` の内訳で分ける。
- advisor を使った応答は、advisor の分が上位の `usage` に入っておらず、`usage.iterations` の `advisor_message`（advisor のモデル付き）にだけある。iterations があれば回ごとにそのモデルの単価で数える。
- Haiku 5.5 は、1 回の入力（キャッシュの読み書きを含む）が 10 万トークンを超えたリクエストだけ高い単価になる。
- `speed: fast` は fast mode の単価、`inference_geo: us` は 1.1 倍で数える。
- `subagents/` のログも含め、サブエージェントの分は親セッションに入れる。

テストの実行: `uv run --no-project python -I -m unittest discover -s tests`
