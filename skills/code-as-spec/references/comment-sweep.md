# 広い範囲のコメント最適化の進め方

SKILL.md「4. レビューと既存コメントの最適化」の振り分けを、repo 全体や数百ファイルの範囲に当てるときの手順。振り分けの基準そのものは SKILL.md が正本で、ここには繰り返さない。

## 分割

- 依存の層や機能のディレクトリで切り、担当どうしでファイルが重ならないようにする（例: `src/domain` / `src/api` / `src/shared` + scripts + 設定 / web の大きい機能 1 つ / web のその他の機能 / web の基盤 / tests）。1 担当は数千〜1 万数千行が目安。
- 並列に委譲するときは、振り分けの基準を一時ファイル（OS の一時ディレクトリ）に 1 枚書き、各担当の指示は「最初にそれを読む」+ 担当範囲だけにする。基準に必ず入れるのは次の 5 つ。
  - 5 区分と、SKILL.md の「修正する」の 4 つの型・「追加する」の条件
  - コメント以外（コード、識別子、フォーマット、import 順）は変えない。バグに気づいても直さず報告する
  - 何も実行しない（git の log / blame / show だけ可）、commit しない
  - 着手前に `GLOSSARY.md` と `docs/adr/` を読む
  - 報告の形: 区分ごとの件数、手を入れた行の `file:line → 区分 → 理由`、理由を確かめられず残したもの、気づいたコードの問題

## 担当ごとの受け入れ

1. コメント以外の行が変わっていないかを機械的に見る。出力が空なら合格。出たら差分を読み、コメントの移動に伴ってコードの行が上下しただけ（削除行と追加行が同じ内容）か、CSS のブロックコメントの継続行かを確かめる。それ以外のコード変更は手で直さず `git restore --source=HEAD -- <path>` で戻す。

   ```bash
   git diff -U0 -- <担当のパス...> | grep '^[+-]' | grep -v '^[+-][+-][+-] ' \
     | grep -vE '^[+-]\s*(//|/\*|\*|\{/\*|#|<!--)' | grep -vE '^[+-]\s*$'
   ```

2. 削除した行のうち、数値・外部仕様・「〜しない」を含むものは、本当に what だけかを読み直す。
3. 担当が根拠として挙げた外部ライブラリの挙動は、`node_modules` のソースで 1 度確かめてからコミットする（担当の推測がそのままコメントに入るのを防ぐ）。
4. 担当ごとにコメントだけのコミットを作る。本文には、直した型（旧称、指し先切れ、位置ずれなど）と、外した経緯の要点を書く。

## 全担当の後の横断確認

担当ごとの判断は揃わない（ある担当が直した旧語を、別の担当が残す）。全担当をコミットしたあとで、`GLOSSARY.md` の _Avoid_ の語と改名前の名前をコメントの中だけから横断検索し、残りをそろえる。

```bash
git grep -nE '(//|/\*|\* |\{/\*).*(<Avoid の語>|<旧称>)' -- src tests scripts tools
```

置換で語を差し替えたら、和文と語の間に残った余分な空白も詰める。

## 報告

ユーザーへは次の 3 つを返す。

- 手を入れた種類と件数の概要（全行の一覧は返さない）
- 理由を確かめられず残したもの（根拠の無い数値、repo の外への言及）。判断はユーザーに任せる
- 見つかったコードの問題（未使用の state・schema、テストが常に通る待ち方、ADR との食い違いなど）。直すかどうかはユーザーに確認するか、別のコミットで直す
